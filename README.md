# LLM-Assisted Complex Task Planning: Task Decomposition, Structural Representation, and Task Allocation

This repository presents **six furniture assembly tasks selected from recorded experiments**, covering task decomposition, Task Decomposition Matrix (TDM) representations, multi-robot task allocation, and conflict resolution. Summary statistics from the main experiments are also provided.

## Research Overview

- **LLM-based multi-agent task decomposition:** Three LLM agents classify tasks, assign task levels, and generate task structures. Example retrieval and validation feedback support the generation of subtasks and their dependencies.
- **Task structure representation and reasoning enhancement:** We propose the Task Decomposition Matrix (TDM), together with matrix encoding and graph reconstruction algorithms. We prove a one-to-one correspondence between isomorphism classes of in-tree task graphs and equivalence classes of TDMs, establishing lossless representation for this class of task graphs.
- **Multi-robot task allocation and conflict resolution:** Task structure representations guide LLMs in predicting task attributes and assigning robots. Constraint checks are then used to identify allocation conflicts and support their repair.

## Main Experimental Results

| Experiment | Evaluation Setup | Successful Trials / Total Trials | Success Rate |
| --- | --- | ---: | ---: |
| Standalone task decomposition | 47 tasks, 5 runs per task | 199 / 235 | **84.68%** |
| Representation comparison: without TDM | 60 tasks, 5 runs per task | 133 / 300 | 44.33% |
| Representation comparison: with TDM | 60 tasks, 5 runs per task | 244 / 300 | **81.33%** |
| Standalone task allocation | 60 tasks, 5 models, 5 runs per task–model pair | 1484 / 1500 | **98.93%** |
| End-to-end task planning | 47 tasks, 5 runs per task | 197 / 235 | **83.83%** |

- The representation comparison measures the feasibility of initial candidate allocations **before feedback or repair**. Using TDM improves this rate by **37 percentage points**.
- Standalone task allocation uses manually verified task structures as input and evaluates the allocation procedure, including feedback and repair.
- End-to-end task planning uses task structures generated by the decomposition procedure. A trial is counted as successful only when both task decomposition and final allocation succeed. Its evaluation conditions therefore differ from those of standalone task allocation.

## Prompt and Model API Outlines

The [prompt outline](interfaces/prompt_outline.json) lists the inputs and outputs for task classification, task-level assignment, structure generation, attribute prediction and allocation, and validation feedback. The [model API interface](interfaces/model_api.py) provides only a method signature. The endpoint, API key, and model name are left blank in the [configuration example](interfaces/model_config.example.json).

These interface files illustrate how the stages connect; they do not implement actual model calls. No API key is required to inspect the matrices, models, or saved results. The public files do not contain the prompts used in the experiments, the example retrieval library, or online service configurations.

## Sources and Scope

The furniture models and images come from the [IKEA Furniture Assembly Environment](https://github.com/clvrai/furniture). The [original project license](third_party/furniture-LICENSE.txt) is included. Task decomposition outputs, matrices, and allocation results are selected from the experimental records of this research.

This repository provides an overview of the research and selected experimental results. Full experimental datasets, core implementations of unpublished work, the prompts used in the experiments, internal logs, and materials related to follow-up research are not included in this public release.
